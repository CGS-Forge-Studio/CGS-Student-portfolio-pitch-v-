## 3. Core Application Scope (Frontend-Focused)
Build the **CGS HUB — Student Portfolio** web application featuring a unified navigation layout faithful to `webapp design.html` and `Design Rule.md`, covering four core modules:

### A. Attendance Record (Connected to Local Workspace)
- Connect the Attendance Record module directly to the data/files inside `D:\Users\visha\Music\Forge Studio\Student portfolio`.
- Inspect the directory for any existing attendance datasets (e.g., `.json`, `.csv`, `.xlsx`, `.db`, or existing API/config files). If no attendance dataset exists yet in that folder, create a structured attendance data file inside `D:\Users\visha\Music\Forge Studio\Student portfolio` and connect the frontend to read from it dynamically (using a lightweight local Node/Vite dev middleware or API route if needed so updates to the file reflect in the UI).
- Display overall attendance percentage, subject-wise or monthly breakdowns, present/absent/late counts, and a clean visual attendance log/calendar.

### B. Academic Record (10 Sample Entries)
- Pre-populate the Academic Record view with **10 realistic, detailed sample records** covering core school subjects, terms/semesters, exam types (Midterms, Finals, Lab Practicals, Standardized Assessments), marks/grades, credits/weightage, and GPA/percentage trends.
- Include filtering/sorting by term or subject and summary KPI cards (e.g., Cumulative GPA/Percentage, Highest Scoring Subject, Total Credits/Assessments).

### C. Achievements Made (10 Sample Entries)
- Pre-populate the Achievements section with **10 diverse, realistic student achievements** (e.g., science olympiads, hackathons, robotics/hardware competitions, research publications, sports, leadership roles, and certifications).
- Each achievement card/entry should display the title, category badge, date, issuing organization, rank/award level, and a concise description. Include category filters (e.g., All, Academic, Technical, Extracurricular).

### D. Digital Vault for Students (10 Sample Files + `+` Upload + 1 GB Quota)
- Build an interactive **Digital Vault** where students store and organize study materials (notes, PDFs, lab reports, reference sheets, slides).
- **Pre-populated Data:** Add **10 realistic sample study files** with varied file types (`.pdf`, `.docx`, `.pptx`, `.png`, `.xlsx`, `.md`), upload dates, subject tags, and realistic file sizes (e.g., totaling ~320–450 MB out of the 1 GB quota).
- **Add File Action (`+` Button):** Include a prominent **`+` button** that opens a file picker/upload modal allowing the student to upload extra files from their device into the vault (with optional subject/category tagging, preview/download actions, and delete functionality).
- **Strict 1 GB Storage Limit:**
  - Enforce a hard maximum storage quota of **1 GB (1,024 MB)** per student across all files in the vault.
  - Display a real-time storage usage bar and exact metrics (e.g., `412 MB / 1.00 GB used • 612 MB remaining`).
  - Automatically recalculate used/remaining storage whenever files are added via the `+` button or deleted.
  - Prevent uploads that would push total storage past 1 GB, showing a clear validation alert explaining the remaining space.
